## 2. 벤치마크 결과 비교 (수치 충돌 분석)

### A. 각 마일스톤별 FPS/지연 지표 비교
1. **1단계 PoC 단독 결과 (60.56 FPS / 7.12ms 내부 지연):**
   - **조건:** 1920x1200 해상도, DXGI 캡처 + RGB565 변환만 수행 (타일 차분, 압축, 디코딩, JSON 쓰기 배제).
   - **해석:** 순수 화면 캡처 및 포맷 변환의 물리적 병목 하한선.
2. **2단계 PoC 워크스페이스 재실행 결과 (15.77 FPS / 17.35ms 평균 내부 지연):**

   - **특이사항:** `Mirage Driver` 가상 디스플레이 감지 조건 및 압축/복원 연산 부하가 더해져 FPS가 **15.77 FPS**로 저하됨.
   - **해석:** 실제 타일 기반 인/디코딩 루프가 활성화된 현재 파이프라인의 실질 데이터.
3. **참고용 로컬 scratch 결과 (47.79 FPS / 7.51ms 평균 내부 지연):**
   - **조건:** 시뮬레이션 부하(Case B/C)를 10프레임당 1회로 분리하여 캡처 낭비를 줄인 테스트 결과 (Mirage Driver 및 스냅샷 보존 등 환경 조건에 따른 편차 존재).

## 4. J1800/J1900 + RAM 2GB 예상 성능 분석 (Speculative / 검증 필요)

호스트 PC 대비 Celeron J1800/J1900 CPU가 **약 4.5배 느리다**고 가정하고, 타겟 해상도별 픽셀 비율(1920x1200 대비)을 적용하여 수학적으로 추정한 대략적 지연 시간입니다. **실제 실장비 성능 측정은 테스트용 단독 실행(EXE) 파일을 빌드하여 배포한 후 진행할 예정이므로, 현재 시점에서는 예측 수치로 두고 평가는 보류합니다.**

* **타겟 해상도 비율:**
  - `1024x768` (XGA): 1920x1200 대비 **34.1%**의 픽셀 수 (768개 타일)
  - `1600x900` (HD+): 1920x1200 대비 **62.5%**의 픽셀 수 (1450개 타일)
  - `1080x1920` (FHD): 1920x1200 대비 **90.0%**의 픽셀 수 (2040개 타일)

### [검증 필요] J1800/J1900 해상도별 예상 합산 내부 지연 (평균)
* **`1024x768` 기준 (XGA):** 17.35ms * 0.341 * 4.5 = **약 26.6 ms (검증 필요)**
* **`1600x900` 기준 (HD+):** 17.35ms * 0.625 * 4.5 = **약 48.8 ms (검증 필요)**
* **`1080x1920` 기준 (FHD 세로):** 17.35ms * 0.900 * 4.5 = **약 70.3 ms (검증 필요)**

> [!WARNING]
> - 100% 전체 화면 변경 시뮬레이션(Case C) 시 호스트 PC에서도 인코딩 지연이 **42.69 ms**가 기록되었으므로, J1800/J1900 환경에서는 **인코딩만으로 100~200ms 이상의 지연이 발생할 가능성**이 높습니다.
> - 따라서 모션 시의 해상도 축소 및 화질 저하 알고리즘은 타겟 환경 통과를 위해 필수적입니다.

## 6. 다음 단계 필수 검증 및 측정 보강 요구사항

1. **J1800/J1900 병목 분석용 추가 지표 수집:**
   - **컨텍스트 스위칭(Context Switching) 및 스레드 수 계측:** WebRTC의 다중 스레드 구동 시 J1800 CPU 자원 고갈을 막기 위해 Agent 프로세스의 active 스레드 수 및 초당 컨텍스트 스위칭 발생 빈도 측정 추가.
   - **물리 메모리 점유율(Working Set) 프로파일링:** J1800/J1900 실장비의 2GB RAM 제약 조건 하에서 메모리 누수나 가상메모리 스왑(Swapping)이 일어나는지 모니터링하기 위해 작업 세트(Private Working Set) 크기 기록 추가.
   - **CPU 커널/유저 타임 계측:** CPU 연산 병목이 JPEG 인코딩(User Time)에 있는지, 혹은 DXGI/GDI 캡처 관련 Syscall이나 커널 경합(Kernel Time)에 있는지 확인하기 위한 분리 측정 추가.

2. **FPS 수치 요동(60.56 vs 47.79 vs 15.77) 표준 격리 측정 방안:**
   - **화면 자극(Screen Stimulus) 표준화:** 화면 무변화 시 DXGI가 자동 타임아웃되어 FPS가 떨어지는 현상을 제어하기 위해, 벤치마크 수행 시 정적 모드(Static Mode - 0% 변경)와 동적 모드(Controlled Dynamic Mode - 60Hz 재생 비디오 자극 강제)를 명시적으로 제어하여 측정하도록 표준 프로토콜 정의.
   - **구간별 파이프라인 격리 측정:** 시뮬레이션 부하(Case B/C)나 루프백 디코더 루프의 영향을 배제하기 위해, CLI 플래그(예: `--mode capture-only`, `--mode encode-only`, `--mode loopback-full`)를 이용하여 인코딩/디코딩 오버헤드를 물리적으로 분리 실측.

3. **기존 ZOOK의 E2E 지연 baseline 측정:** 기존 제품과의 명확한 대조군을 확보하기 위해 Visual Ping 테스트를 ZOOK 환경에서 선제 구동하여 baseline 수치를 획득해야 합니다.

4. **네트워크 전송 결합:** WebSocket/UDP 기반 전송망을 결합하여, WebRTC 대비 Context Switching 오버헤드와 패킷 손실에 따른 p95 E2E 지연 변동폭을 검증해야 합니다.
