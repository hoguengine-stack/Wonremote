# 다른 PC Codex에 전달할 프롬프트

이 PC의 WonRemote **Viewer만** 아래 시험본으로 설치하고 검증해줘. 보조 AI 에이전트를 생성하지 말고 직접 진행해. 이 요청은 이 PC의 Viewer 시험 설치 승인이다. 다른 제품 설치, 원격 PC 변경, 공개 배포·자동 업데이트 정책 변경은 승인하지 않는다.

## 정확한 시험본

2026-09-15 추가: 두 제품의 정식 업데이트 경로에 `v0.1.94`가 게시됐다. 기존 뷰어의 **업데이트 확인 → 업데이트 실행**을 우선 사용한다. 구버전 0.1.93의 실제 업데이트 프로그램에서 새 버전 인식과 서명·다운로드 해시를 확인했다. 기존 Agent 정책은 변경하지 않았으며, 이 PC에서는 Viewer만 설치·검증한다. 아래 직접 다운로드는 업데이트 경로가 실패했을 때의 동일 파일 대안이다.

- 파일: `WonRemote-Viewer-0.1.94-test-20260915.exe`
- 다운로드: https://github.com/hoguengine-stack/Wonremote/releases/download/viewer-test-0.1.94-20260915/WonRemote-Viewer-0.1.94-test-20260915.exe
- 버전/아키텍처: `0.1.94`, Windows x86 (64비트 Windows에서도 이 파일 사용)
- 크기: `20318430` bytes
- SHA-256: `F70F20E5D40C40910B724E6B3595BE58A31C9ED0B4F61ACACA68AC07EA35761D`
- Authenticode: 미서명. 알고 있는 시험본 상태이며, Windows 경고·승인을 우회하거나 보안 설정을 끄지 않는다.
- 이 파일은 기존 GitHub latest 설치본과 다르다. 위 주소에서 직접 다운로드하고 아래 크기·해시를 확인한다. 임의로 latest 설치본으로 대체하지 않는다. 2026-09-15 비로그인 다운로드 HTTP 200 및 전체 파일 해시 일치를 확인했다.

## 대상과 보존

1. Viewer 시험 PC는 `59F19451`이다. 로컬 WonRemote 설정 등 확인 가능한 정보로 현재 PC를 식별하고, 불일치하면 설치하지 말고 보고한다. 사용자 인증 정보는 출력하지 않는다.
2. 기존 Viewer 실행 경로·버전·사용자 설정을 확인하고 복구용으로 백업한다. 이 PC에 설치된 Agent와 그 설정은 건드리지 않는다.
3. 파일 크기와 SHA-256을 먼저 검증한다. 일치하지 않으면 실행하지 않는다.
4. 진행 중 원격 세션을 확인해 사용자 작업 손실 없이 종료한 뒤 Viewer만 업데이트한다. 필요한 Windows 승인은 사용자에게 맡긴다.
5. 재실행 후 실제 Viewer 버전, 로그인·장비 목록·사용자 설정 보존을 확인한다. 설치 프로그램 종료 코드만으로 성공 처리하지 않는다.

## 실제 확인

- 원격 대상 `82220F6D`에 연결해 움직이는 화면과 마우스 입력을 확인한다. 이 대상 PC의 Agent 설치는 원래 Codex가 담당하므로 여기서 다시 설치하지 않는다.
- 테스트용 메모장에서 한글 타이핑 중 Ctrl+A/C/V, Shift+방향키, Alt+Tab, 한영 전환을 확인한다. 단축키 대신 글자가 입력되거나 눌린 키가 남으면 실패로 기록한다.
- 창 전환·접속 종료·재접속 후 키보드와 마우스가 계속 동작하는지 확인한다.
- 원격 연결이 끊기면 중앙 안내와 재접속 버튼으로 장비 목록 새로고침 없이 복구되는지 확인한다. Android의 연결 가져오기 검증은 Android 참여가 가능할 때만 수행한다.
- Ctrl+C/V는 원격 PC 클립보드 안에서 동작하고, 이 PC 클립보드는 명시적 보내기 버튼으로만 전달되는지 확인한다.
- 원격 파일 가져오기에서 선택한 테스트 파일이 이 Viewer PC로 자동 저장되는지, 받은 폴더 열기가 이 PC의 폴더를 여는지 확인한다. 기본 저장 폴더 변경·재실행 보존·동명 파일 미덮어쓰기·해시 일치도 확인한다.
- 장비별 모니터·확대·화질 설정과 메모·담당자·연락처가 저장·검색·재실행 후 유지되는지 확인한다.
- 원격 PC 잠금·로그아웃·재부팅, 업데이트·롤백은 별도 사용자 확인 없이 실행하지 않는다. PIN·클립보드·개인 문서 내용은 기록하지 않는다.

보고는 `설치 결과 / 실제 통과 항목 / 실패 재현 순서 / 미실행 항목 / 버전·파일 해시`로 짧게 정리해줘. 모의 검사나 화면 연결 표시만으로 실제 입력·전송 성공을 판단하지 마. 문제가 발견되면 기존 설정과 백업을 보존하고, 원래 작업의 소스를 임의로 재작성하거나 전체 배포하지 말아줘.
