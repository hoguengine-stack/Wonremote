# 성능·요청·비용

[작업 선택표](../DEVELOPMENT_GUIDE.md)에서 이 작업에 해당할 때 읽는다. 다른 작업 문서를 전부 읽을 필요는 없지만, 변경이 다른 경계에 영향을 주면 해당 문서를 추가한다.

## 성능과 비용은 사용자 경계에서 측정한다

- 체감 지연, 처리량, CPU, 메모리, 저장 공간, 배터리, 네트워크와 과금 중 중요한 항목에 목표를 둔다. 근거 없이 모든 항목에 숫자를 만들지 않는다.
- 비교는 같은 작업·장비·데이터·네트워크 조건에서 수행한다. 평균뿐 아니라 필요한 경우 p95/p99, 최댓값, 장시간 사용과 실패 조건을 본다.
- 내부 함수 시간과 사용자에게 결과가 표시된 시간을 구분한다. 고성능 개발 PC 결과를 저사양 장비 성능으로 보고하지 않는다.
- 라이브러리나 전송 방식의 명성 대신 실제 병목을 측정한다. 최적화 전후에 정확성과 자원 사용을 함께 확인한다.
- 요청·타이머·리스너·재시도·저장 쓰기를 바꿀 때 필요성과 수명 주기를 검토한다. 같은 데이터에 폴링과 구독을 중복 사용하지 않는다.
- 요청이 바뀌는 범위에는 시작 비용, 하루 유휴 비용, 동시 호출, 다시 연결될 때의 비용, 읽는 문서량과 쓰기량을 계산한다. 호출 수만 줄이고 결과 데이터량을 놓치지 않는다.
- 시간·횟수 제한, 중복 실행 방지, 취소, 지수 백오프와 지터를 필요한 경로에 적용한다. 인증·권한·할당량 오류를 빠른 반복 요청으로 악화시키지 않는다.
- 비용 검증은 가짜 시간·에뮬레이터·격리 환경을 우선 사용한다. 운영 부하와 과금은 별도 승인 없이 발생시키지 않는다. 코드 수정이 이미 소진된 외부 할당량을 복원했다고 말하지 않는다.
