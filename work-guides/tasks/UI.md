# 화면·입력·접근성

[작업 선택표](../DEVELOPMENT_GUIDE.md)에서 이 작업에 해당할 때 읽는다. 다른 작업 문서를 전부 읽을 필요는 없지만, 변경이 다른 경계에 영향을 주면 해당 문서를 추가한다.

## 사용자가 편하게 끝낼 수 있게 만든다

- 사용 빈도와 작업 맥락에 맞춰 정보 밀도와 조작 순서를 정한다. 기능 소개보다 실제 작업을 첫 화면에서 시작할 수 있게 한다.
- 조작에는 익숙한 표현을 쓴다. 명령은 버튼, 선택은 메뉴나 탭, 이진 상태는 토글이나 체크박스, 수치는 적절한 입력·슬라이더를 사용한다.
- 작동하지 않는 버튼이나 실제로 연결되지 않은 모형 UI를 완성 기능처럼 배치하지 않는다. 사용할 수 없는 이유와 회복 경로를 제공한다.
- 빈 상태, 로딩, 지연, 오류, 권한 거부, 재시도, 오프라인, 취소를 해당 기능의 일부로 구현한다. 사용자가 이미 한 입력을 이유 없이 잃게 하지 않는다.
- 화면 크기, 방향, 글자 크기, 긴 번역, 소프트 키보드, 안전 영역에서 잘림과 겹침을 확인한다. 키보드·마우스·터치·보조기술 중 지원 대상 입력을 실제로 확인한다.
- 확대할 콘텐츠와 고정 조작부를 분리한다. 콘텐츠를 터치했다는 이유만으로 의도하지 않은 키보드나 창이 열리지 않도록 포커스를 관리한다.
- 접근 가능한 이름, 보이는 포커스, 대비, 충분한 조작 영역을 제공한다. 색상만으로 상태를 구분하지 않는다.
- 위험하거나 되돌리기 어려운 동작에는 대상과 영향을 명확히 보여준다. 반복 모달로 불편을 덮지 말고 불필요한 절차 자체를 줄인다.
