# 협업·인수인계·재개

[작업 선택표](../DEVELOPMENT_GUIDE.md)에서 이 작업에 해당할 때 읽는다. 다른 작업 문서를 전부 읽을 필요는 없지만, 변경이 다른 경계에 영향을 주면 해당 문서를 추가한다.

## 협업과 인수인계

- 독립적으로 나눌 수 있고 조율 비용보다 이득이 있을 때만 협업한다. 작업자를 바쁘게 유지하기 위한 일감, 고정 분담률, 강제 병렬화를 만들지 않는다.
- 목표, 수정 허용·금지 범위, 공용 인터페이스, 완료 증거, 통합 책임자를 정한다. 같은 파일을 동시에 바꿀 때는 명시적으로 조율한다.
- 결과는 작성자의 이름이나 모델이 아니라 실제 변경과 증거로 판단한다. 근거가 없거나 잘못된 결과는 채택하지 않는다.
- 이미 충분한 증거가 있는 작업을 책임자가 형식상 전부 재실행하지 않는다. 위험한 경계·불일치·환경 차이를 중심으로 검토한다.
- 일부 작업이 늦으면 독립적인 일을 진행한다. 필요한 결과가 오지 않았는데 완료를 선언하거나, 필요 없는 작업을 계속 돌려 비용을 늘리지 않는다.
- 인수인계에는 현재 목표, 결정 이유, 실제 변경, 검증 대상·환경·결과, 진행 중인 실행, 미확인 사항과 다음 행동만 남긴다. 오래된 전체 대화를 붙여 넣지 않는다.

## 컨텍스트 압축 후에도 이어갈 수 있게 한다

- 규칙, 현재 작업 상태, 사고 이력은 역할을 분리한다. 같은 사실을 여러 파일에 복사해 서로 다른 최신본을 만들지 않는다.
- 공통 규칙은 한 원본에 두고 다른 문서는 링크한다. 프로젝트별 수치·명령·권한 조건은 별도 문서에서 관리한다.
- 중단·압축 후에는 최신 사용자 요청, 적용 규칙, 현재 작업 기록, 관련 변경 내역을 먼저 읽는다. 완료·보류·진행 중을 복구한 뒤 마지막으로 검증된 지점에서 재개한다.
- 실행 중 프로세스나 미완료 배포가 있는지 확인한다. 앞선 명령이 실패했다는 이유만으로 아무 효과도 없었다고 가정하지 않는다.
- 원격 최신 상태가 필요한 때만 원격 저장소나 서비스를 조회한다. 매 답변마다 fetch·전체 검사·전체 빌드를 자동 실행하지 않는다.
- 기록에 없는 작업을 했다고 추정하지 않는다. 현재 요청이 바뀌었으면 이전 목표를 계속 수행하지 않는다.

## 짧은 작업 기록과 완료 보고

다음은 필요할 때 사용하는 템플릿이다. 작은 작업은 한 문단으로 줄여도 된다. 기존 이슈나 작업 문서가 충분하면 새 파일을 만들지 않는다.

```text
목표와 사용자 관찰:
완료 조건 / 유지 조건 / 제외 범위:
확인된 경로와 사실 / 추정 / 미확인:
변경과 결정 이유:
검증: 대상 버전·환경, 명령 또는 조작, 결과, 재사용한 증거의 범위
빌드·배포·설치 상태 / 남은 위험과 복구 방법:
중단 시: 진행 중 작업, 다음 행동, 필요한 외부 조건
```

완료 전에는 사용자 요청과 실제 결과를 한 번 대조한다. 지원하기로 한 경로에서 목표가 충족됐고 필요한 검증이 확보됐을 때 그 범위만 완료로 말한다. 남은 작업, 미검증 환경, 실패와 경고는 짧고 구체적으로 밝힌다. '완벽하다'는 표현으로 확인 범위를 넓히지 않는다.
