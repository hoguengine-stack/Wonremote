# 보안·데이터·설치

[작업 선택표](../DEVELOPMENT_GUIDE.md)에서 이 작업에 해당할 때 읽는다. 다른 작업 문서를 전부 읽을 필요는 없지만, 변경이 다른 경계에 영향을 주면 해당 문서를 추가한다.

## 보안·데이터·설치 경로를 함께 설계한다

- 인증, 권한 부여, 소유권 검사는 신뢰할 수 있는 경계에서 수행한다. 버튼을 숨긴 것만으로 접근이 제한됐다고 판단하지 않는다.
- 최소 권한을 사용하고 고권한 동작을 좁은 구성요소로 분리한다. 고권한 실행 파일·스크립트·설정은 일반 사용자가 교체할 수 없는 위치와 권한으로 보호한다.
- 로컬 통신도 신뢰를 가정하지 않는다. 호출자 식별, 접근 제어, 허용 명령과 입력 제한을 둔다. 편의상 임의 실행 경로·명령을 허용하지 않는다.
- 비밀번호, 토큰, 개인정보, 서명 키를 코드·로그·공개 산출물에 넣지 않는다. 비밀정보는 임시 빌드 폴더와 분리하고 복구 경로를 마련한다.
- 파일 삭제·이동 전 최종 경로가 의도한 범위인지 확인한다. 링크·정션·재분석 지점이 다른 원본이나 비밀정보 저장소를 가리키는지 확인한다.
- 데이터 변경은 실패 중간 상태, 재시도, 중복 요청, 동시 수정과 복구를 고려한다. 중요한 저장은 원자성 또는 명시적 복구 절차를 갖춘다.
- 설정과 사용자 데이터를 업데이트·재설치·롤백에서 보존한다. 스키마 변경은 구버전과 신버전의 읽기·쓰기 및 복구 가능성을 구분한다.
- 일반 설치만으로 준비가 끝나도록 구성한다. 필요한 권한 절차와 거부 시 동작을 설치·업데이트 흐름에서 명확히 처리하고, 매 실행 때 불필요하게 다시 묻지 않는다.
- 기존 제품은 허용된 사용 관찰과 공개 자료로 비교한다. 코드·자산·비공개 인터페이스의 이용은 권리와 라이선스를 별도로 검토한다.
