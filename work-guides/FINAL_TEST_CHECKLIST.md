# 최종 통합 테스트

대상: Windows `82220F6D`, `59F19451`, Android `1D42C9F9`만 사용한다.
실장비 테스트는 아래 순서로 한 번에 진행한다. 원래 개선 항목 2번의 진단·복구 기능 추가는 제외한다.

## 시작 조건

- [ ] 최신 수정으로 새로 만든 설치본의 버전·해시를 기록한다. 기존 0.1.94 파일은 최신 수정 포함 여부를 확인하기 전 사용하지 않는다.
- [ ] 두 Windows 장비의 기존 등록·설정과 복구용 설치본을 보관한다. 시험 설치·배포 승인과 대상 제한을 확인한다.
- [ ] 테스트용 메모장 문서와 파일만 사용한다. 잠금·로그아웃·재부팅은 저장할 작업이 없는 때에 진행한다.
- [ ] 실행한 장비/Viewer·Agent 버전/결과/실패 화면을 기록한다. 실패 시 다음 설치나 전체 배포로 넘어가지 않는다.

## 1. 설치·일반 실행·업데이트

- [ ] 에이전트를 일반 더블클릭으로 실행한다. 상태 창이 열리고, 권한 설정을 기다리는 동안에도 창이 응답한다.
- [ ] 설정 승인을 취소해도 창이 멈추지 않는다. 권한이 필요한 조작 실패를 정상 제어 성공으로 표시하지 않는다.
- [ ] 승인하면 기존 실행이 정리된 후 관리자 실행으로 전환한다. 동일 에이전트가 중복 실행되지 않고 등록 정보가 유지된다.
- [ ] 설정을 기다리는 중 트레이에서 종료한다. 종료한 앱이 뒤늦게 자동으로 다시 실행되지 않는다.
- [ ] 에이전트 하단 여백·상태·버튼·긴 식별자를 확인한다. 글자 줄바꿈이나 버튼 잘림 없이 필요한 정보를 볼 수 있다.
- [ ] 지정 Viewer만 유휴 상태에서 업데이트한다. 제어 중 설치하지 않으며, 설정을 보존한다. 비지정 장비는 대상 미리보기에서 제외되어야 한다.
- [ ] 시험 업데이트 실패 후 무한 재시도가 없고, 정상 재시도가 가능하다. 복구용 이전 버전으로 되돌린 후 등록·설정·연결을 확인한다.

## 2. 연결·재접속·Windows 입력

- [ ] 연결 상태가 연결 준비/화면 대기/화면 표시/끊김을 구분한다. 화면을 받기 전 정상 표시 중으로 오인하지 않는다.
- [ ] PC Viewer 연결을 Android가 가져간 뒤 Android 연결을 종료한다. PC 중앙의 끊김 안내와 재접속 버튼으로 장비 목록 새로고침 없이 다시 연결한다.
- [ ] 짧은 네트워크 단절 후 재접속하고, 실제로 움직이는 화면과 입력을 확인한다. 정지된 마지막 화면을 성공으로 판단하지 않는다.
- [ ] 한글 타이핑 도중 Ctrl+A/C/V, Shift+방향키, Alt+Tab, 한영키를 연속 사용한다. 단축키 대신 문자가 입력되거나 전환이 늦지 않는다.
- [ ] Ctrl/Shift를 누른 상태에서 창 전환·연결 종료 후 다시 접속한다. 키가 눌린 채 남지 않는다.
- [ ] 원격 Ctrl+C/V는 원격 PC 안에서만 동작한다. 로컬 클립보드는 명시적 보내기 버튼을 눌렀을 때만 전달된다.
- [ ] 잠금→PIN 화면→로그인 전환에서 화면과 입력을 확인한다. PIN 값은 테스트 기록·스크린샷에 남기지 않는다.

## 3. Android 조작·화면

- [ ] 세로/가로 전환 시 상단 시스템 바와 화면·하단 버튼이 겹치거나 잘리지 않는다. 최초 접속은 가로 폭 맞춤이며 세로 화면은 상단에 놓인다.
- [ ] 화면과 검은 여백에서 확대·축소·이동한다. 하단 조작부는 확대되지 않는다.
- [ ] 상대 터치패드 이동, 좌/우클릭, 더블클릭, 끌어놓기, 두 손가락 스크롤을 실제 PC에서 확인한다. 커서 위치와 클릭 위치가 맞는다.
- [ ] 드래그 중 손가락 추가·회전·연결 종료 시 눌림이 해제된다. 다중 모니터에서도 좌표가 맞는다.
- [ ] 키보드 버튼만 Android 키보드를 연다. Fn/Ctrl/Alt/Shift와 화면 터치는 키보드를 임의로 열지 않는다.
- [ ] 키보드 높이를 바꾸어 세로모드에서 원격 화면이 키보드 위에 보이는지 확인한다.
- [ ] Windows/Insert/Delete/방향키/F1~F12 및 고정 단축키를 사용한다. 누름 상태 표시·해제와 재실행 후 고정 목록 보존을 확인한다.
- [ ] 제어 화면에서 뒤로가기 한 번은 안내, 두 번째는 목록으로 이동한다. 목록에서도 같은 방식으로 두 번째에 앱이 종료된다.

## 4. 파일·진단 저장

- [ ] 원격 파일 가져오기에서 파일을 선택하면 Viewer PC에 자동 저장된다. 받은 폴더 열기는 원격 PC가 아닌 Viewer PC 폴더를 연다.
- [ ] 기본 저장 폴더를 바꾸고 재실행한다. 새 위치를 유지하며, 같은 이름의 기존 파일은 덮어쓰지 않는다.
- [ ] 양방향 전송의 취소·재시도·네트워크 중단 후 이어받기를 확인한다. 원본과 받은 파일의 SHA-256이 일치해야 한다.
- [ ] 완료 직전 연결이 끊겨도 재시도 후 파일이 손상되지 않는다. 전송 중 원본이 바뀌면 성공으로 처리하지 않는다.
- [ ] 쓰기 권한 없는 폴더·용량 부족·저장 취소를 확인한다. 실패를 완료로 표시하지 않고 재시도할 수 있다.
- [ ] Android 파일 선택/저장과 저장 제공자 취소·실패를 확인한다.
- [ ] 진단 미리보기와 내보낸 파일 내용이 일치한다. 인증 정보·클립보드·입력 내용 등 민감 정보가 포함되지 않는다.

## 5. 장비 정보·개별 설정

- [ ] 장비 메모·담당자·연락처·최근 연결 표시를 저장하고, 검색·그룹 전환·앱 재실행 후 확인한다.
- [ ] 에이전트 상태 갱신 이후에도 사용자 메모·상호명 등 수정 내용이 보존된다.
- [ ] 두 장비에 서로 다른 모니터·확대·화질·입력 방식을 지정한다. 재접속 후 각각 복원되고 다른 장비 설정을 덮어쓰지 않는다.

## 6. 성능 및 종료 조건

- [ ] 자동 모드에서 정지 화면/화면 변화/전송 혼잡을 비교하고 CPU·메모리·입력 지연을 기록한다. 혼잡 해소 후 화질·반응이 회복되는지 확인한다.
- [ ] 실제 저사양 대상에서 변경 전후 동일 조건의 입력→표시 p95/p99를 측정한다. 고성능 시험 PC 결과로 저사양 합격을 대신하지 않는다.
- [ ] 미완료·실패 항목을 남기고 공개 배포 여부를 별도로 판단한다. 연결 성공이나 설치 완료만으로 전체 합격 처리하지 않는다.

현재 상태: 최신 시작 경로 수정은 소스 검사만 수행했다. 최신 설치본 생성·배포와 위 실장비 항목은 수행하지 않았다.
