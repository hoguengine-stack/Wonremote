# 범용 개발 지침: 작업 선택표

프로젝트·모델·언어와 관계없이 사용하는 지침이다. **해당 행의 문서만 먼저 읽고, 실제 영향 경계가 늘면 추가한다.** 한 작업에 여러 행이 적용될 수 있다. 프로젝트의 더 엄격한 필수 조건을 이 선택표로 생략하지 않는다.

| 지금 하는 일 또는 바꾸는 경계 | 읽을 문서 |
| --- | --- |
| 요구 분석, 원인 조사, 설계, 기능 추가·수정 | [구현](tasks/IMPLEMENTATION.md) |
| 화면, 반응형, 키보드·마우스·터치, 접근성 | [UI·입력](tasks/UI.md) |
| 인증·권한, 데이터, 설치, 파일·비밀정보 처리 | [보안·데이터](tasks/SECURITY_DATA.md) |
| 지연·크기·자원 사용, 요청·리스너·재시도·쓰기 | [성능·비용](tasks/PERFORMANCE_COST.md) |
| 검사 선택·완료 판정, 빌드·배포, 장애 복구 | [검증·전달](tasks/VERIFICATION_DELIVERY.md) |
| 협업, 인수인계, 중단·압축 후 재개 | [협업·재개](tasks/HANDOFF.md) |

## 선택 예

- 문서 정리: 검증·전달의 문서 검사 기준만. 제품 빌드·보안 전체 점검은 하지 않는다.
- 버튼 입력 오류: 구현 + UI·입력 + 검증·전달. 다른 프로세스 권한까지 영향이 확인되면 보안·데이터를 추가한다.
- 구독 중복 요청: 구현 + 성능·비용 + 검증·전달.
- 설치·업데이트: 구현 + 보안·데이터 + 검증·전달.
- 압축 후 재개: 협업·재개와 현재 작업에 해당하는 문서, 작업 기록·변경 내역만 복구한다.

## 읽기 범위

- 짧고 자명한 질문·번역·문구 수정은 관련 세부 규칙이 없다면 이 문서에서 멈춘다.
- 이미 읽은 규칙은 현재 문서와 적용 범위가 그대로면 매 명령마다 다시 읽지 않는다. 압축으로 내용이 사라지거나 규칙·범위가 바뀌면 필요한 부분을 다시 읽는다.
- 현재 작업 상태는 기존 작업 기록에서 해당 항목만 확인한다. 사고 이력은 증상·모듈·오류로 검색해 관련 항목만 연다. 원인이 불분명하면 검색 범위를 단계적으로 넓힌다.
- 파일을 나눈 것만으로 모델의 정확한 문서 선택이나 토큰 절감량이 보장되지는 않는다. 필요한 경계를 놓치지 않는 선택 절차와 간결한 기록이 핵심이다.

다른 프로젝트 적용과 문서 역할은 [안내](README.md)를 참고한다.
